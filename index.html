MÓDULO 01

¿Qué es HTTP y cuáles son sus pilares?

HTTP (Hypertext Transfer Protocol) es un protocolo de la capa de aplicación diseñado para transmitir recursos hipermedia. Sigue un modelo cliente-servidor estricto, donde el flujo siempre comienza con una petición enviada por el navegador.

Capa de Aplicación

Simple y legible por humanos

A diferencia de los protocolos binarios crudos de capas inferiores, los mensajes HTTP/1.1 se diseñaron para ser legibles y depurables directamente por personas, viajando en texto plano estructurado.

  • Corre sobre la capa de transporte (TCP o QUIC/UDP)
  • Independiente del tipo de contenido transportado
  • Inspeccionable desde la pestaña Red del navegador
Extensible por Naturaleza

Cabeceras (HTTP Headers)

HTTP puede incorporar nuevas capacidades sin romper versiones anteriores. Si un servidor o navegador no reconoce una cabecera personalizada o reciente, simplemente la ignora de forma segura.

  • Permite control de caché granular (Cache-Control)
  • Negociación de formato (Accept, Content-Type)
  • Políticas de seguridad y CORS para APIs cruzadas
Stateless pero con Estado

Sin estado... ¿pero con sesiones?

HTTP es sin estado (stateless): no guarda memoria entre dos solicitudes consecutivas. Para resolver esto sin perder velocidad, MDN documenta el uso de las Cookies y cabeceras Set-Cookie, permitiendo crear carritos de compra y logins de usuario.

Ciclo de Conexión

Apertura, Transmisión y Reuso

Antes de enviar un mensaje HTTP, el cliente abre una conexión de transporte mediante un handshake TCP (más TLS si es HTTPS). En HTTP/1.1 las conexiones son persistentes (Keep-Alive) para no pagar el costo de conexión en cada archivo.

El User-Agent

Cualquier herramienta que actúe en nombre del usuario: Chrome, Firefox, curl o un script. Siempre es quien inicia la conexión.

Las Funciones del Proxy

Almacenamiento en caché (CDN), filtrado contra ataques (firewalls), balanceo de carga entre réplicas y autenticación previa.

El Servidor Web

Atiende la solicitud, ejecuta lógica si es dinámica y devuelve el recurso final con la cabecera adecuada (Content-Type).

Evolución: De Bloqueo a Multiplexación y QUIC

El mayor desafío de la historia web ha sido la latencia. Observa cómo cada generación resolvió el cuello de botella del transporte:

Simulador Comparativo de Conexiones

Descargando 6 recursos web (CSS, JS, Imágenes)

HTTP/1.1: Bloqueo de cabeza de línea. Los recursos deben esperar a que el anterior termine.
HTTP/1.1 (1999)

Head-of-Line Blocking

Texto plano. Solo puede enviar una petición a la vez por conexión. Si la primera se retrasa, las demás quedan congeladas en cola.

HTTP/2 (2015)

Multiplexación Binaria

Convierte los mensajes en tramas binarias intercaladas. Todas las peticiones viajan en paralelo a través de una única conexión TCP.

HTTP/3 (2022+)

QUIC sobre UDP

Elimina el bloqueo TCP en la capa de transporte. Si se pierde un paquete WiFi/móvil, las demás transmisiones continúan sin detenerse.
